# 2026 微信小程序开发竞赛路线图

## 作品定位

“今天吃啥”不是菜谱浏览器，而是一套从“家里有什么”到“今天做什么”的轻量决策工具。用户选择或识别现有食材，系统结合饮食目标、忌口和菜谱营养信息，给出可解释的推荐结果，并继续完成收藏、分享、计划和采购。

核心价值：

- 减少每天选菜的决策成本
- 提高现有食材利用率，减少浪费
- 对推荐原因、缺少食材和饮食冲突进行明确说明
- 在不替代专业诊疗的前提下提供通用膳食参考

## 竞赛差异点

### 1. 可解释推荐

推荐卡片必须回答三个问题：为什么推荐、已有多少食材、还缺什么。匹配分数是辅助决策信号，不能包装成医学或营养学结论。

### 2. 饮食安全边界

忌口是硬过滤条件，健康人群是推荐条件。详情页对冲突进行二次提示；营养值明确标记为估算值；慢性病、孕期、婴幼儿和过敏人群提示咨询专业人士。

### 3. 从识别到采购的完整闭环

目标演示流程：拍摄冰箱食材 -> 用户确认识别结果 -> 结合档案推荐 -> 查看推荐解释 -> 加入本周计划 -> 自动汇总缺少食材 -> 生成购物清单 -> 做完后反馈。

## 开发优先级

### P0：答辩前必须完成

1. 替换所有随机占位图，统一为清晰的 3:2 横版菜品图片。
2. 对真机完成核心流程回归，并录制一条无网络依赖的备用演示视频。
3. 校对 20 道菜的营养值、适宜人群、慎用人群和文字表述。
4. [已完成应用内能力] 明确隐私政策、用户数据用途、存储位置和删除方式；提交前仍需同步填写微信公众平台隐私保护指引。
5. 准备 3 分钟演示脚本、架构图、创新点和异常场景说明。

### P1：形成作品闭环

1. 拍照识别食材：优先采用成熟视觉服务，识别结果必须让用户确认和修正。
2. [基础版已完成] 周计划：支持把菜谱加入本周日期和早中晚餐，同一餐次可明确替换或删除；后续增加同类菜连续出现提醒。
3. [基础版已完成] 购物清单：按计划去重汇总食材，支持勾选和手动增删；后续结合用户库存标记真正缺少的食材。
4. 云同步：使用微信云开发同步档案、收藏、计划和反馈，本地缓存保证弱网可用。
5. [基础版已完成] 推荐反馈：记录“不喜欢”“食材不齐”“做过了”等显式反馈；后续可结合云同步做匿名统计。

### P2：提高技术和数据说服力

1. 扩展档案：过敏原、年龄段、目标、每日热量范围、烹饪时间与设备。
2. 推荐评分：综合食材覆盖、忌口、健康目标、时间、历史反馈和菜品多样性。
3. 营养依据：为营养数据保留来源、份量和更新时间，支持后台校验。
4. 数据分析：只采集完成核心体验所需的匿名事件，并提供关闭和删除路径。
5. 无障碍与性能：检查字号、对比度、触控区域、首屏耗时和包体积。

## 技术方案建议

### 拍照识别

- 客户端用 `uni.chooseMedia` 获取图片并在上传前压缩。
- 云函数保存临时文件并调用视觉识别服务，密钥不得下发到小程序端。
- 服务端返回标准化食材 ID、名称和置信度，不直接触发推荐。
- 客户端展示可增删的确认页，低置信度项目默认不选中。
- 图片默认短期保存或识别后删除，并在调用前说明用途。

### 云端数据

建议集合：`users`、`profiles`、`favorites`、`meal_plans`、`feedback`。所有读写按 `openid` 做权限校验，不允许客户端指定其他用户身份。首次启动仍以本地数据工作，登录后再进行有冲突提示的合并。

### 推荐模型

第一阶段保持规则模型，便于解释和答辩。评分可拆分为：食材覆盖 40%、健康适配 25%、时间适配 15%、用户偏好 10%、多样性 10%。忌口和过敏原始终先硬过滤，再参与排序。

## 隐私与合规

- 不把健康人群选择描述为诊断结果。
- 不承诺治疗、降糖、降压、减肥等医疗效果。
- 采集图片、健康偏好或行为数据前，说明用途、范围和保存期限。
- 不在客户端保存云服务密钥，不在日志记录原始健康档案或图片地址。
- 提供清空本地档案、删除云端数据和撤回授权的入口。
- 当前版本没有账号和云端个人资料，已提供饮食档案、收藏、在线缓存的分项删除与本项目本地数据一键清除入口。
- 当前版本已关闭 uni 统计和云初始化 `traceUser`，后续若重新启用统计或账号能力，必须同步更新告知、授权和删除路径。
- 正式提交前以当届官方规则、平台审核规范和隐私保护指引为准逐条核验。

## 三分钟演示脚本

1. 20 秒：展示痛点，家里有食材但不知道做什么，特殊饮食人群还需要避开冲突。
2. 35 秒：在“我的”设置健康目标与忌口，说明信息保存在本机或经授权同步。
3. 45 秒：选择或拍摄食材，确认识别结果，展示匹配度、已有食材和缺少食材。
4. 35 秒：进入详情，展示营养估算、制作步骤、冲突提醒、收藏和分享。
5. 30 秒：加入周计划，自动生成购物清单并勾选采购状态。
6. 15 秒：展示技术架构、规则可解释性、隐私边界和后续数据闭环。

## 风险记录

- 远程随机图片会直接削弱内容可信度，是当前最高优先级风险。
- 菜谱与营养数据目前为静态演示数据，答辩时必须如实说明数据来源和边界。
- 纯随机的“帮我决定”不能冒充智能推荐，应说明候选集已先经过匹配与忌口过滤。
- 拍照识别存在误识别风险，必须保留人工确认步骤。
- 云端功能不能成为现场演示的单点故障，应保留本地数据和失败降级路径。
